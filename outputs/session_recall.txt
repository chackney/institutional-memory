## 📋 Policies (with Effective Dates)

### 1. Production Access Policy
**Effective: 2026-05-15** — supersedes the January 2026 version. *(Source: memory/policies.md — Production Access Policy; original doc: policy-update-2026-05-15.md)*

Triggered by incident **PROD-INC-04-2026** and the company's rapid headcount growth (pairing model didn't scale).

**Three access levels:**
- **Read-only** — 3 working days tenure + Prod Access Foundations certification + just-in-time IAM request.
- **Read-write** — unchanged from previous policy.
- **Privileged** — unchanged from previous policy.

**Read-only request process (new):**
1. Complete **Prod Access Foundations** course in BTS Learning portal (90 min, self-paced).
2. Pass the assessment.
3. Request via **IAM platform** (link in completion email) — no Slack ticket, no SRE pairing.
4. Access granted **just-in-time**, scoped to a **4-hour window** per request; re-request as needed.
5. Manager **notified** per request; sign-off only required for initial certification.

**Tenure requirement:** 3 working days (reduced from 2 weeks). Access requestable from Day 4.

**Migration:** Engineers with read-only access under the old policy retain it through **2026-06-30**, then must certify or lose access.

**What was eliminated:** SRE pairing sessions, Slack `#sre-access-requests` tickets, and the old urgent/exception path (24-hour temp access via on-call SRE — not carried over in the new policy).
